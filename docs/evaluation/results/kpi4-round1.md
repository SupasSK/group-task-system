# KPI-4 ความครบถ้วนของ log — รอบที่ 1 (16 ตุลาคม 2569)

- เครื่องมือ: `evaluation/kpi4-logs.mjs` (commit `d315ffb` ก่อนรัน) ทำทุกการกระทำผ่านหน้าเว็บที่ deploy แล้วด้วย Playwright ใช้บัญชี 5 บทบาท (หัวหน้า, สมาชิก, สมาชิกสอง, ผู้ร่วมทำ, คนที่ถูกนำออก)
- นิยามที่กำหนดไว้ในหัวสคริปต์ก่อนรัน: การกระทำที่กติกากำหนดให้บันทึกหลายเหตุการณ์ (เช่น สร้างกลุ่ม = `group_created` + `member_added`) นับเป็นชุด log ที่คาด ไม่ขาดไม่เกิน, payload ต้องมีทุกคีย์ที่บังคับใน AGENTS.md ค่าตรงกับที่ทำ ผู้บันทึกถูกคน และไม่มีคีย์ต้องห้าม
- ผลดิบ: `kpi4-round1.json`, `kpi4-round1.log`

## ข้อสังเกต
- `member_added` ที่บันทึกโดย RPC `join_group_by_code` มีคีย์เสริม `via: "join_code"` ซึ่งไม่อยู่ในรูปแบบ `{role, email?}` ของ AGENTS.md หน้าเว็บใช้คีย์นี้แสดงข้อความ "เข้าร่วมกลุ่มด้วยรหัส" จึงควรเพิ่มคีย์นี้ในเอกสาร AGENTS.md ไม่ได้ทำให้เกณฑ์ไม่ผ่าน
- การบังคับใส่เหตุผลอยู่ที่หน้าเว็บ (`TaskEditModal`) ฐานข้อมูลไม่ได้บังคับ หัวหน้าที่เรียก API ตรงจึงแก้กำหนดส่งได้โดยไม่มี log ข้อนี้อยู่นอกขอบเขตของ KPI-4 ที่วัดผ่านหน้าเว็บ แต่ควรระบุเป็นข้อจำกัด
- การทดลองเครื่องมือ (pilot) พบข้อบกพร่องของสคริปต์ 1 จุด: เทียบ payload ด้วยลำดับคีย์ ทั้งที่ `jsonb` ไม่เก็บลำดับคีย์ แก้ก่อน commit เครื่องมือและก่อนรันจริง
